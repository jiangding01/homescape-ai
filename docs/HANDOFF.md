# 工程交接与决策记录

> 2026-10-15 起由新的工程负责人接手。本文只记录代码与 ADR 之外的背景、约束和未决事项；架构见 `ARCHITECTURE.md` 与 `adr/`。
> 标记：**[确认]** 已明确或有证据；**[未决]** 尚未得到业务方正式答复。

## 1. 产品定位

- [确认] 长期目标：从真实户型出发，用自然语言持续修改家装空间，并即时、可解释、可撤销地反映到可编辑 3D；按可生产化标准设计，而非一次性 Demo。
- [确认] 第一条闭环：真实户型 → 校正可信空间 → 客厅方案 → 自然语言连续修改 → 实时 3D → Undo / Replay / Save。
- [未决] 首发用户（C 端业主 / B 端设计师 / 内部人员）、项目归属、MVP 验收指标、上线时间、预算。

## 2. 技术约束

- [确认] JEV（TypeSafe）是 `typed_decision` 的首个 Provider，不是强制绑定；可替换或与其他模型协同，需经一致评测。
- [确认] Babylon.js 是首个 Renderer Adapter，不是最终选型；是否改用 Three.js / R3F 由整屋性能评测决定。
- [确认] 当前真实户型样本均为网络公开图片，可用于外部模型实验。公司或客户数据接入前须另行取得授权与合规审批。
- [未决] 部署地域、移动端优先级、单次推理预算、端到端延迟目标、公司户型 Schema 与真实 SKU / GLB 的获取。

## 3. 户型识别现状（2026-10-15）

- 私有 Corpus（不入 Git）：Pilot A 10 张、Pilot B 11 张户型图；人工 GT 已批准 2 个（case-001、case-004），case-b005、case-b011 已有待人工审核的草稿，case-b008 因尺寸数字不可辨认、比例尺无法确认而暂停（仍计入覆盖率分母）。
- case-b011 来自带「商用须授权」水印的图库图片，只用于私有语料内部评测，不得提交或商用。
- 经典像素扫描 Raster Extractor：20 张中 10 张无法生成 Candidate；case-004 正式 Benchmark 房间召回 0%、比例尺误差 84%。
- 视觉大模型盲测（2 个有 GT 的 Case）：房间召回 100%、平均 IoU 98%、房间类型准确率 100%、比例尺误差 < 1%、门窗召回约 80%、客厅尺寸误差 ≤ 4 cm。样本量小，需用可复现脚本扩大验证。
- 已发现：网络户型图常被非等比缩放，横纵每米像素可相差 10%–17%。当前 Calibration 只有单一比例，导致已批准 GT 的纵向尺寸偏差约 10%（像素坐标本身无误，补纵向标尺即可修正）。
