# ADR 0017：户型识别主路径改为“视觉大模型预填 + 人工确认”

- Status: Accepted
- Date: 2026-10-15

## 背景

PR #16 的经典像素扫描 Raster Extractor 在首批 20 张网络公开户型图上真实运行：

| 指标 | 结果 |
|---|---|
| 生成 Candidate | 10 / 20（Pilot A 2/10，Pilot B 8/10），其余为 `no_orthogonal_outline` |
| case-004 正式 Benchmark | 房间召回 0%、房间 IoU 0%、门窗召回 0%、比例尺误差 84% |

同期对 2 个已批准 GT 的 Case 做了视觉大模型盲测（模型只看原图，未接触 GT；输出经转换后由 `floorplan-benchmark.mjs` 正式评测）：

| 指标 | case-001 | case-004 |
|---|---|---|
| 房间召回 / 精确率 | 100% / 100% | 100% / 100% |
| 房间平均 IoU | 98.0% | 98.2% |
| 房间类型准确率 | 100% | 100% |
| 比例尺误差 | 0.3% | 0.5% |
| 门窗召回 | 83% | 79% |
| 客厅 IoU / 长宽误差 | 99.3% / ≤ 2 cm | 99.3% / ≤ 4 cm |

局限：样本仅 2 个；盲测使用多轮裁剪放大的智能体流程，单次识别约 10 分钟，未等同于生产调用方式；需要用可复现脚本在更多样本上复核。

此外，盲测发现网络户型图普遍存在非等比缩放（横纵每米像素相差 10%–17%），单一比例尺会让面积系统性偏差约 10%。

## 决策

1. 户型识别主路径改为：上传原图 → 视觉大模型输出房间多边形、类型、门窗与尺寸读数 → 用户在标注工作台快速确认（重点是客厅）→ Importer + Validation。
2. 人工快速确认是产品的必备环节，而不只是兜底：工作台优先保证“改得快”（画布上直接放门窗、草稿自动保存、手柄按屏幕尺寸）。
3. 经典像素扫描不再作为主路径投入；保留现有代码，未来仅考虑作为“边吸附到墙线”的辅助。
4. 比例尺按横纵两轴标定，并显式记录来源（assumed / annotated / extracted / structured）；假设比例尺阻断 Finalize。
5. 识别 Provider 仍遵循 ADR-0002：视觉大模型作为可替换的 Extractor 接入，统一输出 FloorPlanDraft，进入同一 Benchmark。
6. 评测主指标改为面向下游：客厅是否找到、客厅尺寸误差（cm）、门窗召回、从上传到可用的人工时间；全屋 IoU 作为诊断指标。现有评测工具冻结，不再扩展流程与门禁。

## 后果

- 需要服务端模型 API Key 才能实现可复现的视觉大模型 Extractor；公司或客户数据接入前仍需合规审批（见 `docs/HANDOFF.md`）。
- case-b005、case-b008 的人工 GT 暂缓，优先用可复现脚本扩大样本，再按失败类型决定是否需要 OCR、墙线吸附等补充。
- 已批准 GT 的像素坐标有效，仅需补充纵向标定。
