# ADR 0018：几何内核——内表面房间边界与成对边推导墙体

- Status: Accepted
- Date: 2026-10-15

## 背景

设计审查确认了一组同源的几何问题：

1. `Room.boundary` 与 `Room.wallIds` 是两份互不校验的真值；示例户型用贯穿多个房间的长墙，导入器却按房间边逐条生成墙。
2. 导入器只在两条房间边端点完全相同时才识别共享墙（`floorplan-draft-importer.ts`，量化到 0.001 px 的端点 key）。T 型接头与人工标注误差都会导致墙体重复、门无法连通房间。
3. 没有约定房间边界是墙中心线还是内表面；Planner 贴墙放置时未扣除墙厚，沙发会嵌入墙内。
4. 靠墙候选按整面墙长度取比例位置，长墙的 0.75 处可能已落在隔壁房间；候选朝向与所选的墙侧无关，约一半背对房间。
5. `footprintInsidePolygon` 只检查角点与边中点，L 形房间内凹角处会误判。

真实标注数据显示：相邻两个房间沿内表面描边时，对应的两条边平行、相向，间距约等于墙厚（case-004 厨房与次卧之间 7 px ≈ 0.13 m）。这正是推导墙体的可靠依据。

## 决策

1. **房间边界约定为墙体内表面**（净空地面轮廓），单位米，从 +Y 俯视统一为逆时针绕向，由 Validation 强制。标注规范已采用内表面。
2. **墙体由房间边成对推导**：两个房间各取一条边，若平行、法线相向、间距落在墙厚区间（默认 0.05–0.40 m）且投影重叠长度足够，则重叠段生成一面共享墙：中心线取两边中线，厚度取实测间距，来源标为从图面推断。未配对的边段生成外墙：向房间外侧偏移半个墙厚，厚度为假设值。一条房间边可被切分为多段，以支持 T 型接头。
3. **墙记录两侧房间**：每面墙记录其两侧的房间（外墙一侧为室外）。房间的墙列表由推导结果生成，不再单独维护。
4. **门窗绑定到墙段**：导入器把“房间边 + 偏移”换算到包含它的墙段；跨越多个墙段的门窗生成待复核问题。共享墙上的门和开口推导出房间连接；外墙上的门连接到室外。
5. **多边形运算使用成熟库**：引入 `polygon-clipping`（MIT）处理包含与重叠判断，家具占位“在房间内”定义为占位减去房间后面积近似为零。
6. **Planner 沿房间边段生成靠墙候选**，朝向由该边的房间内法线决定；因边界已是内表面，贴墙距离为半个家具进深加净空，不再额外扣除墙厚。
7. **核实坐标方向**：导入器把图片像素 y 映射为 z。需要用非对称户型对比俯视渲染与原图，确认不是镜像；若是镜像则修正映射。
8. **兼容**：HomeSpatialModel 的 schemaVersion 升级；示例户型迁移为内表面约定（由中心线向内收缩半个墙厚）。

## 暂不处理

曲线墙、带洞房间、跨楼层的楼梯与竖井、完整的半边数据结构编辑能力。当前推导结果足以支撑客厅设计闭环，后续按需要扩展。

## 后果

- 墙厚第一次有了来自图面的实测依据，外墙厚度仍是假设值并保持“未确认”。
- 房间边界与墙体不再是两份独立真值，示例数据与导入数据使用同一套约定。
- 依赖墙体结构的模块（导入器、Validation、Planner、渲染器、示例数据）需要同步迁移。
