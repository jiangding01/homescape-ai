# ADR 0019：设计状态以服务端为准并持久化

- Status: Accepted
- Date: 2026-10-15

## 背景

当前设计状态只存在于浏览器内存：刷新页面后导入的户型与全部 Revision 丢失；Planner 与 Revision 在前端执行，服务端无法校验；修订、操作与家具对象的 ID 由前端计数器生成，刷新后从 1 重新开始（`design-command-1`、`revision-planner-1`、`object-<operationId>`）。一旦持久化，刷新后的新操作会覆盖已保存的同名对象，修订 ID 也会与历史冲突。

## 决策

1. **服务端是设计状态的唯一真值。** 前端提交“操作列表 + 基线版本 + 原始请求”，服务端运行 Planner 与 Revision 引擎（与前端共用同构包），约束不通过返回 422 并附违规原因。前端可在本地预演，但不以本地结果为准。
2. **ID 由服务端生成**（UUID v7）：修订、操作与家具对象 ID 不再依赖前端计数器。
3. **存储使用 Node 内置 `node:sqlite`**，手写 SQL，外包仓储接口，后续可整体替换为 Postgres。Node 最低版本提升到 22.13。数据库文件位于 `apps/api/.data/`（Git 忽略），测试使用内存库。
4. **修订日志只追加。** 每条修订附带修订后的完整 DesignState 快照（状态体量小，换取实现简单）；日志仍可完整重放与审计。撤销 / 重做栈由日志推导，不单独存储。
5. **乐观并发。** 提交、撤销、重做都必须携带客户端所见的最新修订 ID；不一致返回 409，客户端重新拉取后提示用户。
6. **空间模型以不可变版本保存。** 项目指向当前空间模型；切换户型时为新模型开启新的修订时间线，旧时间线保留。
7. **契约包** `@homescape/contracts`：用 zod 定义请求与响应，前后端共用并在运行时校验，替代手抄类型与 `as` 断言。
8. **接口**（前缀 `/api/v1`）：创建 / 读取项目，上传空间模型，提交修订，撤销，重做。现有 `/api/design/interpret` 保持不变。首次启动自动创建示例项目。
9. **存储的 JSON 带 schemaVersion**，读取时经迁移注册表升级到当前版本。

## 不做

- 离线编辑与同步：与乐观并发冲突，当前阶段收益低。标注工作台的本地草稿保存不受影响。
- 登录与多人实时协作：首发用户未定，鉴权暂缓。

## 后果

- 刷新、多设备访问都能恢复同一份设计；修订可审计。
- **无鉴权的写接口只适合本地或内网使用，在加入鉴权前不得公开部署。**
- 前端的状态管理需要从组件内 state 抽离为 store，并改为调用服务端接口。
